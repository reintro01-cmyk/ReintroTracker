# Reintroduction Tracker

Personal web app for following a food-elimination + reintroduction programme:
detox phase → systematic reintroduction → tag each food **Safe / Limit / Avoid**
and let the planner suggest meals that respect those verdicts.

## What's in here

| Slice | What it does |
|---|---|
| **Foods** | The catalogue (`src/data/foods.js`) + the Safe/Limit/Avoid status map per user. |
| **Schedule** | Phase-aware reintroduction calendar — pre / detox / reintro, with priority + group ordering and allergy skips. |
| **Recipes** | A ~1MB curated corpus (`src/data/recipes.data.js`, generated by `pipeline/`) filtered against the user's status map and allergens. |
| **Body** | Weight, measurements, body-fat estimate, weekly averages. |
| **Onboarding** | 5-step wizard (`src/components/onboarding/*`) that captures start date, strategy, food/group priority, and allergies. |

## Stack

- React 19 + Vite 8 (no TypeScript — plain JSX with `jsconfig.json` for path aliases)
- Tailwind 4 via `@tailwindcss/vite`
- Recharts for body-tracking charts
- Supabase (auth + Postgres + edge functions) — see `supabase/`
- Vitest for unit tests
- Python pipeline (`pipeline/`) that ingests IFCT + USDA nutrition data and builds the recipe corpus

## Development

```bash
npm install
npm run dev          # vite dev server on http://localhost:5200
npm run build        # production build → dist/
npm run preview      # serve the production build locally
npm run lint
npm test             # vitest run (one shot)
npm run test:watch   # vitest watch mode
```

The recipe corpus is **dynamic-imported** so it ships as a separate chunk
(`recipes.data-*.js`) rather than bloating the entry bundle. `src/main.jsx`
awaits `loadRecipes()` once before mounting so every downstream consumer can
read it synchronously via `getRecipes()`.

## Architecture

State lives in two hooks consumed by `App.jsx`:

- `src/hooks/useAppState.js` — programme state, foods, status map, body
  measurements, favourites, schedule, persistence + Supabase sync.
- `src/hooks/useAuth.js` — Supabase session, sign-in / sign-up / reset.

UI is organised by feature:

```
src/components/
  tabs/         # Top-level routes — HomeTab, ScheduleTab, FoodsTab, etc.
  recipe/       # Recipe rendering — RecipeCard, SlotCard, ShoppingList
  onboarding/   # Onboarding wizard step components
  body/         # Weight / measurement widgets
```

Meal-planning logic is in `src/utils/mealPlanner.js`:

- `getCurrentPhase()` — pre / detox / reintro based on start date + detox length
- `getRecipesForSlot()` — scored, allergen-filtered candidates for one meal slot
- `getDesserts()` — desserts annotated with `ready` / `pending` ingredient status
- `assembleDayPlan()` — picks one recipe per slot, avoids repeats, respects favourites
- `getEffectiveSlots(mealMerge)` — optional 12+2pm or 4+6pm merged meals

## Supabase

Client config lives at `src/lib/supabase.js` — URL + **publishable** key are
hardcoded. The new `sb_publishable_*` format is client-safe, *but* this only
works if **RLS is enabled on every user-scoped table**.

Migrations are in `supabase/migrations/`. The edge function in
`supabase/functions/generate-recipes/` calls the Anthropic API to generate new
recipes from a phase + macro spec — set the secret with:

```bash
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
```

## Recipe pipeline

`pipeline/` builds the recipe corpus that ships with the app.

1. `ingest_ifct.py` + `ingest_usda.py` — load Indian and US nutrition databases.
2. `extract_recipes.py` — pull curated recipes and normalise ingredients.
3. `tag_corpus.py` + `validate_indb.py` — tag with slot/phase, run coverage checks.
4. `format_recipes.py` — emit `src/data/recipes.data.js`.

Outputs (`pipeline/out/*.sql`, `*.json`) are gitignored — re-run the scripts
to regenerate. The `*.md` coverage reports are kept because they're
diff-worthy documentation.

## Tests

Vitest runs in `node` environment (no jsdom yet), so coverage is on pure-logic
modules: `mealPlanner`, `migrations`, recipe data integrity, recipe scenarios.
Adding component tests will require `environment: 'jsdom'` in `vite.config.js`.
